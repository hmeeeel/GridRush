# GridRush - многопользовательская игра в реальном времени

Игроки на общем клетчатом поле бегут к одному предмету. Кто первым шагнул на клетку предмета - получает очко, предмет появляется в другом месте. Раунд заканчивается по таймеру.

**Стек:** JavaScript. Сервер - Node.js (WebSocket по RFC 6455, HTTP, хранилище через REST Supabase). Клиент - JS + `<canvas>`.


## Управление

Стрелки или WASD (работает и при русской раскладке); удержание - повторные шаги не чаще серверного кулдауна. На телефоне - экранные кнопки; поле подстраивается под размер окна с сохранением пропорций клеток.

## Требования

1. Обеспечить мгновенную синхронизацию действий игроков у всех участников через WebSockets (RFC 6455 написан с нуля).
1. Использовать только JavaScript, без фреймворков.
1. Обеспечить сохранение данных игры между запусками приложения (Supabase через REST).
> **schema.sql:**
> * players: id, token_hash, ник, цвет, счёт, позиция, on_field, created_at, last_seen_at.
> * game_state: единственная строка с версией, счётчиками, предметом и номером раунда.
> * score_log: append-only лог начислений.
> * не хранится: сокеты, кулдауны, буфер дельт, RTT.
1. Учесть конкурентный доступ: если несколько пользователей одновременно редактируют один и тот же элемент, необходимо предусмотреть разрешение конфликтов.
> Реализация - если двое шагнули на предмет в один тик, очко получает тот, чья команда первой взята из очереди. Двойное начисление за один предмет невозможно ни в коде, ни в базе (unique(item_id)).
1. При потере интернет-соединения приложение должно сохранить состояние и восстановить его после переподключения.
> Реализация - клиент автоматически переподключается, сервер держит игрока на поле 20 секунд, пропущенные события догоняются без полной перезагрузки. После долгого отсутствия игрок появляется заново с сохранённым счётом.
1. Развернуть готовое приложение на любом хостинге и предоставить ссылку (развернуто на бесплатном тарифе Render).
